> 适用: 综合判断 / 选型决策 / 体检结论
> 触发词: "优缺点" / "利弊" / "好坏" / "总结"
> M3 vision 评分基线: **8.5/10**

## 字段说明

| 字段 | 必填 | 备注 |
|---|---|---|
| 维度/项 | ✅ | 6 个最舒服 (3-7 都行) |
| 优点 | ✅ | 至少 1 个具体证据 (¥/时间/订单号) |
| 缺点 | ✅ | 至少 1 个触发条件 (什么情况会出问题) |

## 6 维度黄金结构 (体检报告)

1. **价格** — 团费/总价/性价比 (带 ¥ 数字)
2. **行程合理性** — 强度/覆盖/时间分配
3. **酒店** — 星级/位置/真实价位
4. **服务/项目** — 含项/自费/购物点
5. **风险/季节** — 雨季/旺季/淡季差异
6. **应急/退改** — 改签/退款/24h 管家

## 6+6 对称原则

- **优点 ≤ 缺点**: 让用户警惕
- **优点 > 缺点** (如 7+3): 容易让用户轻敌, 不推荐
- **优点 < 缺点** (如 3+7): 红线信号, 应该 ❌ 不推荐

## 优缺点撰写模板 (通用)

### 优点写作公式

```
[具体证据] + [对比/排他] + [对用户的价值]
```

**例** (出行全包):
- ❌ 差: "酒店很好"
- ✅ 好: "酒店真实价位 {{酒店 B 晚均价}}/晚(比 MCP 估 {{MCP 估价}}/晚便宜 32%, 携程实价确认), 私人泳池别墅, 已发确认函"

### 缺点写作公式

```
[问题] + [触发条件] + [用户行动]
```

**例** (出行全包):
- ❌ 差: "酒店可能没前台"
- ✅ 好: "D1 凌晨 00:00-00:30 到酒店, 24h 前台未确认, 可能夜间无服务 — **必须问客服**"

## 跨场景迁移

任何"出行/选型/体检"报告, 优缺点都按 6 维度走:

| 场景 | 优缺点侧重 |
|---|---|
| 跟团游 | 行程/购物点/餐/司机/退改 |
| 自由行 | 签证/机票/酒店/餐厅/应急 |
| 商务考察 | 会议/接送/翻译/资料/网络 |
| 蜜月游 | 私密性/浪漫氛围/纪念品/摄影 |
| 亲子游 | 安全/儿童餐/游乐场/医疗 |

## M3 vision 反馈 (实战)

> "每个优缺点都带具体证据 (¥/订单号/时间), 不空洞"
