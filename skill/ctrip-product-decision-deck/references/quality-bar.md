# Quality Bar — 用户反复要求的 4 个底色

> 5+ 个会话里,用户持续表达 4 类不满。这些**不是单次任务要求**,是**风格偏好**。
> 新会话启动就按这 4 条走。**别等用户喊停**。

---

## 1. 数据真实(数据不真实 = 全部白做)

### 用户原话(2026-06-07)

- "你确定拿到了?"
- "你真的拿到了吗"
- "下次拿到的数据一定要真是完整"
- "你确定信息是真的吗"  ← 反复质疑

### 体现

| 必须 | 必须做 | 错误做法 |
|---|---|---|
| 真抓 SPA | 走 `ctrip_spa_capture.py` + `ctrip_shopping.py` | 用 LLM 总结当一手数据 |
| 多源交叉 | 携程主接口 × wendao × AI_Go_Hotel | 单一 LLM 输出 |
| 显式标源 | "wendao = 间接" / "AI_Go_Hotel = amap 后端" | 标"已独立验证" 糊弄 |
| 4 色标记 | 🟢 携程主 / 🟡 wendao / 🟠 AI_Go_Hotel / 🔴 LLM 推 | 全白板 |

### 自查

- [ ] 每个数据点标了来源?
- [ ] 没出现"已交叉验证"字样(除非真的独立第三方)?
- [ ] 风险点 / 退订 / 装备清单全部真实可查?

## 2. 旅客视角(给"谁"看?)

### 用户原话

- "给谁看呢"  ← **必问,先定客群**
- "站在旅客的角度"
- "关注旅客关注点"
- "关注点都说明白"

### 体现

| 旅客关心(必含) | 内部数据(可省) |
|---|---|
| 7/3 23:59 后损失多少钱 | SH ID 1542841 |
| 凌晨 0:30 出发是为什么 | SegmentNo 4 |
| 巴厘岛旅游税 ¥75/人 | FeeCode CTRIP_FEE |
| 蓝火不保证 | productId 69762187 |
| 6 岁以下/65 岁以上能不能爬 | ObjectType ID |
| 雨季/旱季穿衣 | climate normal 1981-2010 |

### 反例

- 标题"桑提卡固本泗水高级酒店 SH ID 1542841 4星 房型 豪华特大床房"
- 旅客看到 SH ID = 啥?

### 自查

- [ ] 标题/数据是不是"旅客看得懂"的中文?
- [ ] 装备清单、年龄/体力限制、签证、税务 全列了?
- [ ] "违约损失 ¥9,660" 这种**具体数字**而不是"按比例扣除"?

## 3. 配色 + 排版(丑 = 全部重做)

### 用户原话

- "配色那么丑"
- "ppt-master 没有模版吗"  ← 提示去看 templates/charts/

### 体现

- **走 ppt-master 71 图表** (`ls /opt/data/skills/ppt-master/skills/ppt-master/templates/charts/`)
- 13 色板海岛风: #1F4E79 蓝 / #3E6B53 绿 / #C0392B 红 / #D4A017 黄
- editorial 杂志感: Georgia 标题 + Microsoft YaHei 正文
- **真图必嵌** 5 张关键页(P01/P06/P14/P15/P16 + v4 P20)

### 反例

- 纯色块矩形 + 居中白字(像 Word 模板)
- 一上来自己拼 SVG,不看 templates/charts/
- 文字 + 数字 一种字号铺满
- 海岛风用 5 种饱和色撞色

### 自查

- [ ] 至少 5 页嵌了真图(不是 emoji/几何图标)?
- [ ] 用了 ppt-master 71 图表(bar/line/kpi/timeline/matrix/comparison)?
- [ ] 13 色板 + 4 字体 stack 一致?

## 4. 页数 + 密度(一页一个论点)

### 用户原话

- "你的 PPT 一页内容怎么简单"
- "每页都要间接"  ← 详细,密度
- "做详细一点"
- "分析的到位一点"

### 体现

| 场景 | 页数 |
|---|---|
| 1 张产品图,粗看 | 12-15 页(精简) |
| 标准产品 7-10 日 | 21-26 页 |
| v4 高水准(用户反复要求) | 26-28 页(必加 P20 退订风险) |
| 4 产品 × 3 客群交叉 | 30-32 页(决策矩阵) |

**密度**: 1 页 ≈ 1 个明确论点 / 1 个数据可视化 / 1 个客群切片。**不是** 1 页塞 100 字也不是 30 页没信息。

### 反例

- v1 = 10 页太薄(v2 加到 25 页用户才满意)
- v3 = 25 页纯色块,等于 Word 大纲
- 把单日详情塞 1 页(7 行文字 = 旅客看不到任何信息)

### 自查

- [ ] 页数 = 21-28 之间?
- [ ] 翻每页 5 秒,能说出"这页在论证什么"?
- [ ] P20 退订风险 / 客群分流 / 决策树 必含?

## 5. 何时用户会"加场"(每会话 1-2 次)

1. **第一次交 v1** → 用户说"做详细点" / "做详细一点" → 立刻加页数到 26
2. **第二次交 v2** → 用户说"数据确定是真的" → 必走 Step 1.2 (shoppingid)
3. **第三次交 v3** → 用户说"配色丑" / "图够吗" → 必走 Step 1.5 (60+ 张全量图 + M3 视觉)
4. **第四次交 v4** → 用户说"对旅客关心点到位" → v4 必含 P20 退订 / P25 客群 / P24 倒计时

**别等 4 轮** —— **第 1 轮直接做 v4 标准**,**节省 3 轮**。

## 6. 单条命令拼装(给未来 agent)

> 用户说"做一个决策手册"时,直接执行:

```
1. skill_view(name="ctrip-product-decision-deck")
2. 读 references/quality-bar.md(本文件)
3. 1 句话问 4 出行字段(A 段)
4. 跑 run_v4.sh <productId> <cityId> <fromDate> <toDate> <travelers> <audience> 26
5. 5 张关键页必改:P01/P06/P14/P15/P16 + v4 P20
6. M3 视觉选 6-8 张图,嵌 SVG
7. quality_check 0 error → finalize → svg_to_pptx → workspace
8. 报告用 4 色标记真实度
```

**8 步一气呵成**,用户才不会说"做详细点"。
